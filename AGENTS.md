# Agent Notes

## Project shape

- This is a single Clojure/Leiningen library (`net.clojars.macielti/service`), not a workspace or runnable application. Treat `project.clj` as the canonical build and dependency manifest; `pom.xml` is generated by Leiningen and ignored by Git, so edit `project.clj`, not `pom.xml`.
- Run Leiningen commands from the repository root. CI uses JDK 21 for tests and JDK 17 for lint.
- The lifecycle entry point is the Integrant key `service.component/service`. It receives a components map, reads service config from `[:components :config :service]` and routes from `[:components :routes]`, then starts/stops a Pedestal `:sawtooth` Http-Kit connector.
- The 2.0.0 implementation is Http-Kit-based. Do not reintroduce Jetty options or assume `error-handler-interceptor` or `components-interceptor` are installed automatically; consuming applications add interceptors explicitly.
- Keep responsibilities separated by namespace: `service.component` owns lifecycle/wiring, `service.interceptors` owns request helpers, `service.error` owns HTTP-shaped exceptions, and `service.common` owns the health handler.

## Code conventions

- Use `defn` for ordinary helpers, `defn-` or `^:private` for implementation-only helpers, and `s/defn` when a function has explicit Schema input/return annotations, as in `service.error`.
- Prefer destructuring for map-shaped arguments. Keep the whole request/context with `:as` when it is needed; use `[_ {:keys [...] }]` for Integrant lifecycle methods.
- For nested request contexts, destructure the relevant request keys and retain the whole context with `:as` only when it is needed, for example `[{{:keys [json-params]} :request :as context}]`.
- Keep dependent bindings in one `let`; avoid nested `let` forms when the values are related. Use persistent map literals instead of `array-map`, and keep scalar arguments named/typed instead of wrapping them in a map solely for destructuring.
- Use `_` for unused Integrant lifecycle arguments and underscore-prefixed names for intentionally unused values.

## Development and testing

- Resolve dependencies with `lein deps` before verification.
- Run the full suite with `lein test`. The `:dev` profile explicitly includes `test/unit`, `test/integration`, and `test/helpers`; there is no separate integration task.
- Put integration tests under `test/integration/`. Focused examples are `lein test service.interceptors-test` for unit tests, `lein test component-test` for the integration namespace, and `lein test :only service.interceptors-test/query-params-schema-test` for one var.
- Use `s/deftest` and `matcher-combinators.test/match?` for tests where appropriate. `.lsp/config.edn` maps `schema.test/deftest` to `clojure.test/deftest`.
- For Integrant tests, define a `system-components` map with namespaced keys and `ig/ref` dependencies, initialize it with `(ig/init system-components)`, exercise the returned component, and call `(ig/halt! system)` in a `finally` block so cleanup still runs when an assertion fails.
- Use `lein check` for a namespace/compile check. `lein lint` is the CI gate and runs `clean-ns --dry`, `format --dry`, then `diagnostics`; formatting and namespace rules are in `.lsp/config.edn`.
- Apply namespace/format fixes with `lein lint-fix` (or `lein clean-ns-fix` / `lein format-fix`), inspect the resulting diff, and rerun `lein lint`. The fix alias does not run `diagnostics`.
- Use `lein antq` only for intentional dependency updates, then review `project.clj` and rerun verification.
- `lein repl` starts in `service.component`, as configured in `project.clj`.
- Start with the narrowest relevant test, then run the relevant verification commands and inspect the diff before proposing a change.

## Gotchas

- The integration fixture `test/resources/config.example.edn` starts the service on `0.0.0.0:8080`; make sure port 8080 is free before running the integration test.
- Service configuration uses `:host` and `:port` (required by the documented API) plus optional `:worker-threads`, which is passed to Http-Kit.
- The `:dev` profile replaces resource paths with `test/resources`; account for that when debugging fixture loading.
- As checked in, `lein lint` can report a formatting-only failure in `test/integration/component_test.clj`; fix it only when that file is in scope, then rerun lint.
- Verify APIs against the source, tests, and `project.clj` rather than relying on generated files or historical documentation.
